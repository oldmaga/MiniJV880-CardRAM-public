# Remote GUI / Remote keyboard manual

MiniJV880 includes an external PC-side Remote GUI:

    tools/minijv880_remote_gui.py

This tool runs on the development PC. It is not compiled into the MiniJV880 firmware and it is not served by the embedded MiniJV880 HTTP server.

The goal is to provide a practical remote front panel for development, maintenance, testing and documented JV-880 workflows, while keeping the embedded HTTP server small and stable.

The Remote GUI is especially useful when:

- the MiniJV880 unit is not physically close to the PC;
- repeated front-panel tests are needed during development;
- original JV-880 manual procedures are easier to follow with a JV-880-like virtual panel;
- LCD, cursor and LED readback are useful while testing a workflow;
- remote hold gestures are needed, for example DATA hold or PREVIEW hold.

## 1. System prerequisites

The Remote GUI is a PC-side Python/Tkinter tool.

Required on the PC:

- Python 3;
- Tkinter support for Python;
- network access to the MiniJV880 HTTP server.

For full live LCD/LED readback, serial monitor support is also recommended:

- `pyserial`;
- a serial adapter connected to the MiniJV880 debug serial output;
- permission to access the serial device, for example `/dev/ttyUSB0`.

On Debian/Ubuntu-style systems the typical packages are:

    sudo apt install python3 python3-tk python3-serial

If `python3-serial` is not available or a virtual environment is used, install `pyserial` in the Python environment used to run the GUI.

The serial monitor is passive: it reads MiniJV880 serial output from the PC side and does not send commands over serial.

Current serial monitor defaults:

- 38400 baud;
- 8 data bits;
- no parity;
- 1 stop bit.

Remote commands are still sent over HTTP.

## 2. Start the Remote GUI

From the repository root:

    python3 tools/minijv880_remote_gui.py

Example:

    cd ~/MiniJV880-CardRAM-public
    python3 tools/minijv880_remote_gui.py

The GUI opens as a desktop Tkinter application on the PC.

If Tkinter is missing, install the Python Tk package for the system, for example:

    sudo apt install python3-tk

If the serial monitor cannot be started, check that `pyserial` is installed and that the current user can access the serial device.

On many Linux systems this may require membership in the `dialout` group:

    sudo usermod -aG dialout "$USER"

After changing group membership, log out and log back in.

## 3. Connection to MiniJV880

The Remote GUI talks to MiniJV880 over small HTTP endpoints.

Default URL:

    http://192.168.1.50:8080

The URL can be changed in the GUI.

Use the tool only on a trusted local network. Do not expose the MiniJV880 HTTP server to the Internet.

The Remote GUI is not a large web page served by MiniJV880. It is a PC application that sends small HTTP commands to the device.

## 4. Main window overview

The top area contains:

- connection and HTTP status;
- a two-line LCD readback display;
- cursor readback;
- serial monitor controls;
- manual LCD refresh and HTTP fallback controls;
- optional serial log/details.

The lower area contains the remote keyboard/front-panel controls.

Depending on the current version, the GUI may provide two complementary views:

- MiniJV880 current hardware view;
- Original JV-880-oriented panel view.

The MiniJV880 current hardware view reflects the practical button layout available on the MiniJV880 unit.

The Original JV-880-oriented panel view is intended to help follow original JV-880 manual workflows. It is a test-oriented virtual panel, not a claim that the MiniJV880 physical panel is a perfect one-to-one reproduction of the original JV-880.

## 5. Remote button model

The Remote GUI uses the same small HTTP remote-control model used by the firmware-side diagnostic endpoints.

Typical command families include:

    /rraw?a=tap&m=
    /rraw?a=down&m=
    /rraw?a=up&m=
    /renc?d=cw
    /renc?d=ccw
    /rclr

The exact GUI buttons normally hide these URLs from the user.

Conceptually there are three remote button actions:

- tap;
- down;
- up.

A tap is a complete short press generated by the GUI.

A down action starts a held remote button state.

An up action releases a held remote button state.

The `Clear remote` action is a safety reset that releases remote-held states if the GUI and MiniJV880 state become unclear.

## 6. Basic button use

For normal short button presses, use tap/click actions.

Typical examples:

- UTILITY opens the Utility menu;
- SYSTEM opens the System menu;
- EDIT enters edit-related workflows;
- PATCH/PERFORMANCE switches between Patch and Performance areas;
- LEFT and RIGHT move the cursor;
- ENTER confirms the selected operation;
- EXIT-style behaviour depends on the original firmware workflow and the currently selected mode.

The Remote GUI sends commands to the MiniJV880 firmware. The actual result is determined by the emulated JV-880 firmware state, just like with the physical buttons.

## 7. Encoder use

The Remote GUI can send encoder rotation commands:

- clockwise;
- counter-clockwise.

These are sent through the small encoder endpoint:

    /renc?d=cw
    /renc?d=ccw

Use the encoder controls when the original workflow expects VALUE / DATA wheel movement.

Examples:

- scrolling through patches;
- changing a selected value;
- moving through Utility menu options;
- changing a Card/Internal destination when the firmware expects encoder input.

The GUI does not edit JV-880 parameters directly. It only emulates the front-panel action.

## 8. Held buttons and long-press workflows

Some MiniJV880 workflows need a held button.

Examples:

- PREVIEW hold;
- DATA hold for native A/B/I/C or Card/C selection workflows;
- ENTER down / ENTER long-like behaviour while the press is still active;
- TONE SELECT hold, where applicable.

For these workflows, use explicit down/up controls or the dedicated hold controls provided by the GUI.

Important rule:

    always release a held remote button after the test.

If the state becomes unclear, use:

    Clear remote

This is especially useful after an interrupted test, network delay, GUI close, or accidental hold.

## 9. DATA hold and Card/C workflows

In MiniJV880-CardRAM, DATA has a special practical role.

On the physical MiniJV880:

- DATA short press is used for the SR expansion overlay/menu;
- DATA long press is used to pass the DATA button to the original firmware where native A/B/I/C or Card/C selection is needed.

The Remote GUI can help test these workflows because it can explicitly hold and release remote buttons.

Typical areas where DATA hold can be useful:

- Patch Play bank selection;
- Performance Play bank selection;
- Patch Write Internal/Card destination selection;
- Performance Write Internal/Card destination selection;
- Patch Copy source bank selection;
- Performance Copy source bank selection.

The exact behaviour still depends on the current MiniJV880 firmware and on the current JV-880 screen.

## 10. LCD readback

The GUI can read the remote LCD in two ways.

Preferred interactive path:

- passive serial LCD/cursor readback, when the serial monitor is active.

HTTP fallback path:

- `/rlcd.txt` at startup;
- manual `Refresh LCD`;
- event-driven fallback after remote commands when the serial monitor is not active.

The GUI does not use periodic HTTP polling.

When the serial monitor is active, automatic HTTP LCD fallback is skipped.

The LCD cursor is read from the firmware LCD state, not inferred from text content.

Cursor readback can come from passive serial events such as:

    LCDC|ROW=...|COL=...|ENABLED=...|VISIBLE=...|ADDR=...

or from the `CURSOR:` line returned by `/rlcd.txt`.

The firmware suppresses serial flooding from cursor blink-only changes: serial cursor updates are emitted when LCD text or cursor position changes, not for every blink phase.

## 11. LED readback

When the serial monitor starts, the GUI performs one small HTTP read from:

    /rled.txt

This is used to synchronize the initial LED state.

After that, LED/LCD updates should normally come from passive serial events.

LED readback is useful when testing mode buttons, panel state and workflows where the visible LED state matters.

## 12. Display customization

The `Display...` window provides PC-side customization of the remote LCD rendering.

Available settings may include:

- LCD color preset;
- background tone;
- character style;
- text color;
- background/text invert option.

These settings only affect the PC-side GUI display.

They do not change:

- the MiniJV880 firmware;
- the physical LCD;
- the data returned by `/rlcd.txt`;
- the serial LCD events.

The dot-matrix renderer is intended to resemble the character LCD more closely.

The text-based renderers are useful as alternatives when a clearer desktop display is preferred.

## 13. Important safety note about held buttons

The HTTP LCD endpoint `/rlcd.txt` is read-only, but it still goes through the normal HTTP path.

Manual `Refresh LCD` should not be used while remote hold gestures are active, such as:

- DATA hold;
- TONE SELECT hold;
- ENTER down / ENTER long while the press is still active;
- PREVIEW hold.

The GUI avoids automatic HTTP LCD fallback during local hold states, but manual refresh remains a manual diagnostic action.

If a hold gesture is active, release it before using manual refresh.

If the GUI state looks inconsistent, press:

    Clear remote

## 14. Serial monitor

The serial monitor is passive PC-side readback of MiniJV880 debug serial output.

It is useful for:

- live LCD tracking;
- cursor tracking;
- LED tracking;
- checking remote command effects;
- keeping embedded HTTP traffic minimal during interactive testing.

The serial monitor does not send commands over serial.

Remote commands still use HTTP.

The current MiniJV880 debug serial output is normally available on the dedicated debug serial line used by the project. Check the hardware/front-panel documentation for the current wiring notes.

## 15. Settings persistence

The GUI saves its PC-side settings on close.

Default path:

    ~/.config/minijv880_remote_gui/settings.json

If `XDG_CONFIG_HOME` is set, it is used instead of `~/.config`.

Saved settings include:

- MiniJV880 URL;
- HTTP timeout;
- serial port;
- serial baud rate;
- HTTP fallback setting;
- window geometry;
- Show details state;
- Show safety notes state;
- LCD color preset;
- LCD background tone;
- LCD text color;
- LCD background/text invert option;
- LCD character style.

To reset the GUI settings, close the GUI and remove the settings file:

    rm -f ~/.config/minijv880_remote_gui/settings.json

## 16. Typical workflow examples

### 16.1 Open Utility from the PC

1. Start the Remote GUI.
2. Check that the MiniJV880 URL is correct.
3. Press/tap UTILITY in the remote keyboard.
4. Watch the LCD readback.
5. Press/tap UTILITY again or use the firmware-appropriate exit workflow.

### 16.2 Test encoder navigation

1. Open a screen where the JV-880 firmware expects value changes.
2. Use encoder clockwise/counter-clockwise controls.
3. Watch the LCD readback.
4. If the serial monitor is active, verify that updates arrive without manual refresh.

### 16.3 Test DATA hold for Card/C selection

1. Navigate to a workflow where the original firmware expects DATA + encoder.
2. Start DATA hold from the Remote GUI.
3. Rotate the encoder remotely.
4. Confirm that the selected bank/destination changes as expected.
5. Release DATA.
6. Use Clear remote if the state becomes unclear.

### 16.4 Test PREVIEW hold

1. Select a patch or screen where PREVIEW is meaningful.
2. Start PREVIEW hold.
3. Verify that the expected preview behaviour occurs.
4. Release PREVIEW.
5. Use Clear remote if needed.

## 17. Known limitations

The Remote GUI is a development and maintenance aid.

It is not a complete replacement for the physical front panel.

The Original JV-880-oriented panel view is intended to help follow original JV-880 workflows, but MiniJV880 hardware and firmware mapping are practical adaptations.

The HTML remote page and the Python Remote GUI have different strengths:

- the HTML page is simple and portable but has no access to the PC serial monitor;
- the Python Remote GUI is better for interactive testing because it can use passive serial LCD/LED readback.

Network delay can affect remote interaction.

A held remote button should always be released explicitly.

If a command appears interrupted or the state is unclear, use:

    Clear remote

## 18. Troubleshooting

### GUI cannot contact MiniJV880

Check:

- MiniJV880 IP address;
- HTTP port;
- Ethernet connection;
- whether the MiniJV880 HTTP server is enabled;
- whether the PC and MiniJV880 are on the same trusted local network.

### Tkinter is missing

Install the Tkinter package for the system Python:

    sudo apt install python3-tk

### Serial monitor does not start

Check:

- serial device path, for example `/dev/ttyUSB0`;
- baud rate;
- user permissions for the serial device;
- whether `pyserial` is installed;
- whether another program is already using the serial port.

### Permission denied on `/dev/ttyUSB0`

On many Linux systems, add the user to the `dialout` group:

    sudo usermod -aG dialout "$USER"

Then log out and log back in.

### LCD does not update automatically

Start the serial monitor and verify that MiniJV880 serial LCD events are being received.

If the serial monitor is not active, use manual `Refresh LCD` only when no remote hold gesture is active.

### GUI state looks inconsistent after a hold gesture

Press:

    Clear remote

Then repeat the test from a known state.
